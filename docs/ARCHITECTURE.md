# 架构与实现原理

## 从规则到画面

`engine.js` 是纯模拟层，包含关卡、路径、经济、战斗、福利和检查点；不依赖 DOM 或计时器。`game.js` 接收鼠标/键盘操作，推进模拟，维护 localStorage 和音效。`systems.js` 负责福利、进化和战报对话框。`renderer.js` 读取游戏状态，绘制 Canvas；`art.js` 提供 SVG 插画。

```text
鼠标 / 键盘 → game.js → engine.js → 当前战局
                     ↕              ↓
                 systems.js     renderer.js → Canvas
                     ↓
                波次检查点 → localStorage
```

## A* 与建造事务

20×12 网格采用四方向移动，每步成本相同。A* 使用曼哈顿距离启发式，优先队列在这个小地图上直接用数组排序；这是可读性优先的实现，不是大规模寻路性能基准。

建造时先复制障碍集合，检查入口到出口、现存工单到出口，以及当前画饼目标的可达性。全部通过才扣费并写入设备。失败不会先扣钱。重算路线时保留工单正在通过的线段，避免插入设备后出现穿墙或瞬移。

## 画饼与路线

未吃过当前饼的工单先寻路到饼，再寻路到出口；每张饼有自己的 ID 和到期时间。过期后重新计算出口路线。额外行走有收入上限，过长路程又触发红温加速，避免“只把路铺长”成为无代价解法。

## 固定步长

渲染由 requestAnimationFrame 驱动。game.js 将时间累计到 accumulator，按 1/60 秒推进引擎；倍速增加模拟时间。单帧时间差设上限，切出页面时自动暂停，降低后台停顿后一次补算过多的风险。这不能保证任意设备上的帧率，但能把规则步进与显示刷新频率分开。

## 战斗和组合

四种设备各有职责。三级后可选一次互斥进化，福利独立改变射程、伤害、经济或技能。攻击优先级由玩家选择。护盾、装甲和持续伤害分别处理；战报记录有效伤害，包含护盾吸收，不计过量伤害。咖啡增益不叠加，贡献计入实际攻击设备。

## 可复现的福利与检查点

福利池过滤已获得项，用保存的整数种子推进伪随机抽选。界面新开局使用时间生成种子，存档保留种子和待领取候选；刷新不会重新抽一轮福利。这个机制用于游戏复现，不是安全随机数。

检查点只在布置阶段和开波前保存，不保存一波中途的全部弹道。恢复时验证关卡、经费、生命、塔位置、类别、路线、福利及分支，并兼容 v2。损坏记录被拒绝，不能把非法设备带进游戏。localStorage 的存在不代表跨设备或跨来源同步。

## 验证范围

2026-09-23 重跑 39 项 Node 测试，全部通过；包括六关正常预算通关、封路保护、画饼、升级出售、八种分支、福利抽选、特殊敌人、Boss、伤害统计和存档兼容。发布配图来自正常交互的真实页面，没有修改经费或战斗状态。

这不等于所有设备、浏览器版本和布局都经过完整验收。手机推荐横屏，电脑操作更精确；长期平衡性仍欢迎玩家反馈。
